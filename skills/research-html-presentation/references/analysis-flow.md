# Optional editable analysis flow for dataset scroll reports

Every new project with `profile: "dataset-report"` and explicit `outputMode: "scroll-report"` defaults to `analysisFlow.enabled: true`. Read this reference for every such project. Existing projects are not migrated; an author may explicitly disable a new project's flow.

The first graph is generated from the project's existing DatasetRecord, DataTransformRecord, AnalysisRecord, and report metadata, using `scripts/generate-analysis-flow.mjs <project-root>`. Save it as project-root `analysis-flow.json` and treat that file as the immutable restore baseline. Never copy example topic names or invent cleaning, tests, or models that were not performed. The generator refuses to overwrite a populated baseline unless explicitly invoked with `--force`; ordinary editing never calls it.

The browser's AnalysisFlow component starts collapsed. A node opens its description; the editor permits adding and deleting nodes, editing titles and descriptions, moving nodes by pointer or keyboard/buttons, changing its approved color treatment, and adding or deleting connections. Save the editable graph in namespaced local browser storage; show storage errors and unsaved state. Undo, redo, and a confirmed one-click restore are required. Restore reloads the immutable initial graph and persists that baseline in the current edition, including downloaded editions, so reopening does not resurrect imported edits. This is a presentation-only graph: editing it does not mutate the Evidence Registry, official report copy, authoring Patch, source data, or computations. Do not add semantic consistency approval or block free-form graph edits.

The entry does not appear when disabled or in formal report print. The graph may be explored in a modal without changing the report's chapter navigation, chart state, scrollspy, or printState. Keep the full graph available on narrow screens through an internally scrollable canvas and form controls; prevent page-level overflow. Give node and edge controls labels, focus states, keyboard movement, and an Escape close path. The generated graph is a starting point, not an additional finding, claim, or citation registry.

No enable flag is needed: new scroll scaffolds include an empty graph file so the import compiles; replace it with a generated baseline after actual evidence exists and before delivery. `--no-analysis-flow` explicitly disables the entry, independently of `--no-analysis-companion`; the old positive `--analysis-flow` flag remains a compatibility alias. Validate the baseline's structure and live browser editing with `scripts/validate_analysis_flow.mjs <project-root> --runtime`, then run the normal project verifier. Test editing, save/reload, undo/redo, restore, narrow screen, keyboard movement, disabled state, and print exclusion.

The flow toolbar also provides **导出流程** and **导入流程**. Transfer files carry their report identity and initial-graph hash; validate bounded nodes/edges, approved colors, coordinates, unique IDs and resolved connections before importing. Importing a different report/version or malformed file leaves the current graph unchanged and displays the reason. A valid import is undoable and can be saved. Current graph changes are also included in the editor's modification JSON and modified-report HTML; flow editing remains presentation-only.
