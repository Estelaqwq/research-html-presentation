# 通用竖版汇报

## 入口和适用范围

用户先选择展示形式，再判断内容类型。所有新建汇报在形式未明确时使用 SKILL.md 中统一的两选一问题；不根据文件扩展名或是否有CSV替用户决定。明确选择、当前任务已确认或用户说“默认”时直接沿用；未回复不视为默认。

`outputMode: "scroll-report"` 可用于全部受支持的学术汇报 profile。工作进展使用 `work-report`；材料综述、政策阅读、方法说明或混合内容使用最贴近的既有 profile。`dataset-report` 仅用于数据分析本身为任务主体的情形，不作为绕过模式校验的标签。学校身份与商业网站排除边界不变。

一般汇报中的表格、少量CSV或统计只是证据：读取并核查所需字段、计算支撑该模块的值，记录来源和范围，不强制增加探索分析、模型、预测或统计结论。数据分析是主任务时，仍完整执行原有 Dataset Analysis Pipeline 和 v3 合同。

## 内容组织

先确定听众需要理解的主线，再从材料中选择模块，不固定章节数或顺序：

- 工作进展：概览、工作范围、方法、实例或成果、当前状态、后续安排。
- 材料综述：材料范围、主要观点、对照、证据与限制、研究启发。
- 方法说明：问题、操作过程、方法区别、示例、使用条件。
- 混合内容：按实际工作或论述主线组织；数据模块服务于该主线。

一个章节负责一个清楚的讲述任务。先介绍对象，再解释做法，随后展示实例或结果。已完成、进行中、方法已明确但未开展、待核验和尝试后未采用需准确区分；不把准备、回填和独立数据来源混作同样的完成成果。

通用 prototype 使用 hero 和两个真实材料支撑的代表性正文模块，可为方法、对照、工作或进度，不要求存在分析结果。完整汇报从 hero 开始，可用后续安排或有内容的结尾收束；无需另造统计发现或一节只写感谢的 closing。数据报告仍保留原来的 analysis-design、decisive-result、synthesis 和 closing 约束。

## 精炼正文

默认展示重点，不把完整演讲稿放入正文：标题说明具体主题、问题或有依据的判断；模块用必要的短句、关键词、数字和条件表达一个核心意思。选择性加粗判断条件和核心值，避免整段加粗。

简洁不等于抽象。“政策工具与支持对象”宜展开为“提供哪些支持、谁能申请、有哪些条件”；“流程优化”应说明具体改了哪一步。不为了减字删除样本基数、时间范围、来源、失败情况或解释结果所需的限制。口头衔接、长背景和完整讲稿进入可选讲述提示或展开详情。用户明确要求详细阅读版或可照读时再增加解释。

## 版式与模块

使用现有 ReportRuntime：左侧章节目录、右侧连续正文，通用模式加顶部工具栏。延续正式学术视觉风格：浅蓝/白色区域、深蓝层级、细规则线、克制的重点色；暗色继续使用现有主题令牌。内容驱动高度，保持阅读宽度和对齐，不堆固定高度的幻灯片。

`ReportModules` 提供可选的概览重点、顺序步骤、对照表、进度、案例联动、方案标签页和展开详情。按关系选择：比较用对照、步骤用顺序、数量用图表、具体问题用实例；文字能直接讲清就用文字。模块不要求每份报告都有数值、图表、进度条或相同数量的卡片。

JSON 正文支持有限的 `**加粗**` 标记，由 `ReportText` 安全渲染；不用 HTML 注入。动作、数值、差异和判断条件可以选择性强调，避免整段加粗。中性结构样例见 [通用竖版样例](../examples/general-scroll-report/README.md)，不得复制其测试事项作为用户成果。

复杂科学图、FlowSpec、实际数据图表仍沿用共有证据组件和来源规范。简单编号步骤不冒充已执行的实验或算法。交互示意要展示真实机制或实际差别，标记假设与示意；“手动满足数量”不能冒充概率抽样算法。

## 行为与交付

通用工具栏提供汇报模式、可选讲述提示、重置、全屏和打印。章节和当前项由同一 sections 数组派生，维持 hash/history、移动目录和减少动画支持。交互标签页、案例及展开详情可键盘操作；重置恢复声明的默认状态。

默认不为通用报告生成分析助手、数据检查和分析流程图空入口；这些数据分析工具仍只在具备对应分析记录并且任务需要时启用。不要为了通用流程图伪造 AnalysisRecord。Authoring 继续新项目默认启用：通用竖版的编辑入口接入顶部工具栏，桌面和手机均不遮挡正文；16:9控件布局保持不变。静态/离线文字保存使用现有浏览器补丁；受管图片写入仍需本地服务，失败要说明实际原因。

生成项目使用 `scaffold_project.mjs --mode general-scroll-report --profile <profile> --output <new-directory>`。此命令是形式已经由用户选定后的实施步骤，不代替入口询问。`--profile` 默认 `work-report`；原有三种模式保持兼容。

扩展后的静态回归入口为 `scripts/test_general_reports.mjs`，覆盖无数据工作汇报、材料综述、混合内容、未填展示形式的旧项目，以及无效进度/对照表的拒绝路径。其结果不能替代真实浏览器与离线验收。

离线版通过 `export_offline_report.mjs <project-root> [--output <html-path>]` 编译同一个 `src/main.tsx`、sections 和 Authoring Boundary，嵌入脚本、样式及所引用的本地资源，不另写一套报告。默认输出 `offline/index.html`，自包含交付仍需浏览器真实验证。外部文献链接联网后可打开；服务器模型问答不属于离线能力。

## 校验与参考

运行同一个 `verify_project.mjs`，保留来源、身份、章序、编辑、交互、溢出和真实视觉复核。通用模式用报告的内容高度、空尾、字号和证据尺寸检查，不能套固定画布的70%占用或要求不存在的Type A图表。存在图表时仍检查数据、基数、刻度和默认/打印状态。例行材料综述不强制注册统计模型。

有意义的验证覆盖：无数据文件的工作汇报；材料综述；少量CSV与真实案例的混合汇报；原16:9和数据竖版回归。验证桌面、手机、目录、切换、重置、打印、离线和文字保存。截图只作为视觉参考，不提供以后报告的事实。

参考截图位于 `examples/general-scroll-report/reference-calibration/`。它们用于浅蓝/深蓝层级、内容宽度、共有边界、实例联动和工具栏校准，不把参考报告的日期、产品、数字、路径和领域规则带入生成内容。

## 阅读与现场汇报

通用模板的补充说明使用现有 details 模块：阅读时默认展开，切换汇报模式时收起，仍可手动展开；切回阅读时恢复展开。主结论、决定性图表、分母、单位、时间范围和关键限制保留在普通正文中，不能借收起详情隐藏。打印展开全部补充说明，并沿用原有确定性证据状态。讲述提示说明这一段要讲什么、图里重点看哪里，避免照抄正文。

本地编辑的修改文件导入导出与“下载修改版HTML”沿用 [lightweight-editing.md](lightweight-editing.md)。保存到当前浏览器和下载到其他设备是不同操作，界面需给出明确结果。旧项目不自动迁移。
