# Optional research companion for dataset scroll reports

Read this reference for every **new** `profile: "dataset-report"` project with explicit `outputMode: "scroll-report"`. The companion is enabled by default in new scroll reports and starts collapsed. Existing manifests remain unchanged; no project is migrated automatically.

## Product boundary

The report remains a complete, finite academic document with a verified direct answer and deterministic print. The companion is an initially collapsed reader workspace, not a permanent filter sidebar, dashboard, alternative report renderer, or Authoring tool. Put the question field first, show short prompts for the visible section, and offer an explicit all-questions view. Move lengthy data-use and privacy text into a discoverable disclosure. Every section with a registered AnalysisRecord should offer at least one answerable prompt; never invent one to fill a gap. It does not alter formal findings, claims, chart domains, narrative units, evidence values, or report section order. Reader questions and temporary calculations are labelled as exploration. Personal notes are stored separately from `presentation-edit-patch.json`; they cannot become formal findings without returning to the normal analysis, provenance, review, and release process.

## Activation and data contract

For a new scroll report, `node scripts/scaffold_project.mjs --mode dataset-scroll-report --output <empty-directory>` creates `analysisCompanion: { enabled: true, mode: "deterministic", projectId: "..." }` in the manifest. After the real analysis, populate approved aggregate measures and section-specific questions from existing evidence; the scaffold's empty registry is only a placeholder. An explicit `--no-analysis-companion` disables it without showing an empty control. The old positive `--analysis-companion` flag remains a compatibility alias. Do not enable it for a deck or silently migrate existing projects.

The one Evidence Registry owns `analysisCompanion.measures[]` and `analysisCompanion.questions[]`. A measure is a **preapproved aggregate cube**, not raw or row-level data. It declares dataset/analysis/transform/source/claim IDs, an optional visual ID, unit, method, limitations, allowed groups/periods, cells, and `sum` or `weighted-rate` aggregation. `weighted-rate` cells have numerator, denominator, and a value consistent with their ratio times `displayMultiplier` (1 by default; 100 is mandatory for `%`). Periods must have an unambiguous sortable order, such as ISO dates or fixed-width years. Cells are disjoint at the declared group/period grain. Publish only cleared, necessary aggregate cells; apply recorded small-group suppression before packaging. Never infer a new field, expose a sensitive record, or average already averaged values.

Each question binds a finding ID (an existing `AnalysisRecord` with a finding statement), measure ID, claim IDs, source IDs, and one allowed action: `lookup`, `group-compare`, `time-range`, `sensitivity`, `method`, or `registered-finding`. Optional `sectionIds` targets a prompt to sections that already cite that finding; optional `defaultSelection` binds a concrete group/year range. Validate both against report sections and measure dimensions. The last action reads the linked AnalysisRecord and its supporting metrics; it does not create a second finding. Pass the registry's existing `analyses` and `citations` into `CompanionEvidence` at runtime so local suggestions can cite the original records. Generate a suggestion only when the required dimensions and cells exist; group comparison and sensitivity require at least two approved groups/scenarios, time range requires at least two periods, and `registered-finding` requires a finding statement. The deterministic path accepts exact registered questions and bounded unambiguous matches. It explicitly refuses unsupported or ambiguous requests; it never invents a number.

## Optional model API

Only a newly scaffolded dataset scroll report may opt in with `--analysis-companion-llm`. This writes `analysisCompanion.llm: { enabled: true, apiPath: "/api/research-assistant" }` and installs a local same-origin server. Existing projects are never migrated automatically. For DeepSeek, set `RESEARCH_COMPANION_PROVIDER=deepseek` and `DEEPSEEK_API_KEY` in the **server environment**. The default model is `deepseek-flash` and the default endpoint is `https://api.deepseek.com/chat/completions`; this adapter uses JSON output with non-thinking mode and omits OpenAI-only request fields. For another compatible API, set `RESEARCH_COMPANION_PROVIDER=openai-chat`, `OPENAI_API_KEY`, and `RESEARCH_COMPANION_MODEL`; `RESEARCH_COMPANION_ENDPOINT` may select a compatible HTTPS Chat Completions endpoint. `RESEARCH_COMPANION_TIMEOUT_MS` (1000–30000), `RESEARCH_COMPANION_RETRIES` (0–2), and `RESEARCH_COMPANION_PORT` are optional. Run `npm run build`, then `npm run preview:companion`. Without a key, the default `mock` provider exercises the complete protocol offline; a selected provider without a key falls back to deterministic parsing and answers. Never put credentials in manifest, frontend code, report export, local notes, or logs.

The Evidence Registry's optional `analysisCompanion.toolPolicy` is an allowlist over the **existing** measures and AnalysisRecords. It declares `allowedOperations` (`period-total`, `annual-average`, `single-year`, `endpoint-change`, `registered-finding`, `method`), `measureIds`, `analysisIds`, `maxGroups`, and `maxPeriods`. It is not another data source. The server runs question parsing → validated plan → deterministic tool calculation → minimal evidence packet → model wording → programmatic numeric/citation checks. The model receives permitted metadata during planning and only the selected calculated facts, scope, method, citations and limitations during wording. It cannot execute code, read files, request raw rows, or create authoritative numbers. Invalid plans, unsupported years/groups, model failure or timeout return a deterministic answer or an explicit refusal. Model wording with an unrecognized number, country, citation, or causal assertion is discarded. Reader-facing status distinguishes `已核验数据计算`, `AI 辅助解释 · 数值已核验`, and `证据不足`; the offline provider is labelled `离线模拟`.

Only additive annual flow measures may be summed across years when the registered measure has `aggregation: "sum"`. A period total, annual mean, single year, relative percentage change, and absolute endpoint change have different meanings and must be named. Questions containing “average per year” require `annual-average`; growth or decline requires `endpoint-change`; a single-year lookup requires `single-year`. Model plans with a mismatched operation are rejected before calculation. Annual mean is available only for additive annual flow measures. `aggregation: "snapshot"` means one group and one registered year per value; it permits `single-year` and same-year group comparisons, never period totals or annual means. Rates with a denominator use their separately registered weighting method. The model-authored answer must preserve the deterministic conclusion verbatim and may add only a nonnumeric, noncomparative explanation of registered methods or limitations. Never sum per-capita measures, life expectancy, rates, or other snapshots across years. Descriptive association cannot establish causes. Ambiguous ranking questions require clarification. Every dynamic calculation records the question, input scope, parameters, transforms, method, results, unit, source IDs, and timestamp. The record and verified answer may be saved in a **personal** notebook; neither becomes a finding, claim, formal chart, Authoring Patch, nor printed report. Promotion to formal report requires an analyst to register and review a new AnalysisRecord, linked claim/source and visual as applicable, rerun validation, then approve the revised report.

Optional follow-ups carry only a prior, server-validated question and plan as proposed context. The server resolves a short follow-up into an explicit question, validates the new plan against the current Evidence Registry, and computes again. Never trust browser conversation history, inherit a missing field silently, or use a model response as authority for scope. If the reference is ambiguous or outside the allowlist, ask for clarification. Show the reader whether the model service is connected, in offline mock mode, or using the deterministic path. A report-evidence jump may transiently highlight an existing section or chart without changing its axis, baseline, data, or print state.

The generic parser obtains indicator names from each approved measure's `label` and optional `queryTerms`, and group names from `groups` and optional `groupAliases`. The optional `fieldId` connects a measure to an AnalysisRecord `outputFields` entry when a question asks about a registered relationship. Put topic-specific names, aliases, units, and cells in the project's Evidence Registry; do not hard-code a sample dataset into the skill runtime. If a question names multiple measures without a registered relationship analysis, ask the reader to narrow it.

The local answer records question, status, answer, value/unit when applicable, selection, method, dataset/analysis/transform IDs, claim/source/visual IDs, and limitations. Restore clears the exploration selection/result and returns the reader to the report's unchanged default state. If a comparison lacks a cell, or a weighted denominator is zero, return `insufficient`; never interpolate.

The reader notebook stores only answered result snapshots, tags new notes with the report evidence version, flags older snapshots when that version changes, supports individual deletion in namespaced browser local storage, and exports a separately labelled `个人分析摘录.txt` with question, answer, scope, method, source and limitations. It never enters the formal report print or Authoring Patch. Storage failure is visible and does not make an unsaved result look saved. Formal `?print=1` omits the companion entirely and retains declared chart `printState`.

## Verification

Run `validate_analysis_companion.mjs` for enabled projects before runtime checks. It verifies source and claim links, aggregate cell uniqueness, arithmetic, permitted actions, section targeting, default selections, and sensitive-dataset privacy status. Run `validate_report_runtime_contract.mjs` in real browser behavior to check collapsed default, accessible toggle, unsupported-question refusal, reset, Escape, narrow screen, and print exclusion. For a populated project inspect every section's contextual prompts, the all-questions view, one supported question, one changed group or period, notebook persistence/export, evidence jump, and a screenshot at desktop and narrow widths. `scaffoldPlaceholder` may contain empty measures/questions as structure only; it is never a research deliverable.

## Reader exploration controls

For an enabled companion, charts may emit a `zuel:companion-evidence` event carrying only a registered `measureId`, group and period, plus an optional visual ID. The assistant revalidates all three against the Evidence Registry before opening a prefilled question. A keyboard-operable chart control must provide the same path; a raw chart point must never be treated as evidence on its own.

A comparison guide can calculate only against the Registry's aggregate cells: one-year values, period totals for registered additive flows, endpoint changes, and sensitivity of an endpoint ranking. Snapshot measures permit same-year lookups and comparisons only. Each guided run records the input scope, operation, parameters, transforms, method, calculated facts and units, source IDs and timestamp in the same companion result shape used by deterministic answers. It does not create a second finding, claim, citation, or chart data source. Results are temporary, reversible, and excluded from `printState`.

After an answered question, offer up to a few contextual next steps only when the prior validated plan and registered cells support them. A request for an unsupported cause, unavailable field, or missing evidence remains insufficient; where possible, offer a bounded descriptive question the data can answer. Never turn a change in a measured indicator into an unverified mechanism. Sensitivity compares declared end years and states whether absolute and relative rankings agree; it does not silently move a formal figure's baseline or axis.

In interaction QA, exercise a chart-point or keyboard entry, a valid same-year comparison, an invalid snapshot period total, a sensitivity calculation, an insufficient causal question with a supported alternative, an analysis record, reset, narrow-screen layout, notebook separation, and print isolation. Verify that new-project scaffolding copies `companion-exploration.ts` along with the assistant component.
